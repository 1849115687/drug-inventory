# 设计文档 — 药品销售库存管理小程序（PWA）

> 项目目录：`drug-inventory-app/`
> 文档状态：**待设计评审**（2026-08-29）
> 配套文档：`docs/requirements.md`（需求，已确认）、`docs/test.md`（测试，实现阶段产出）
> 本文档覆盖范围：问题陈述、方案与理由、架构、界面与交互决策、文件清单、验收标准、关键决策记录、风险。

---

## 1. 问题陈述

药店/零售店需要一套手机端可用的库存管理工具：店员要能快速登记销售（含拍照识别销售单）、自动扣减库存、看到低库存预警并追溯销售记录。现有方案要么依赖后端服务器（部署成本高），要么纯手动录入（慢、易错）。本项目提供**零后端、纯前端、可离线**的移动端小程序：数据存浏览器 localStorage，拍照识别作为录入加速手段，识别结果人工确认后才写入，确保库存准确。

## 2. 方案概述与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 技术栈 | 原生 HTML + CSS + JS，无框架、无构建步骤 | 体积小、无 node 依赖、部署门槛最低（用户为非开发者） |
| 模块化 | 普通 `<script>` 标签按序加载（**不用 ES Modules**） | `file://` 协议下 ES Modules 受 CORS 限制，手机直接打开 HTML 会失败 |
| 存储 | localStorage（JSON） | 需求规定无后端；药店药品数 + 销售记录量级远低于 5MB 配额 |
| OCR | Tesseract.js，CDN 懒加载 | 需求确认「OCR 为辅助」；懒加载避免首屏卡顿与流量浪费 |
| PWA | manifest + Service Worker | 需求确认「可添加到主屏幕、离线使用」 |
| 界面 | 底部 Tab 单页 + 弹层，移动优先 | 药店场景单手操作、路径短 |

## 3. 架构设计

### 3.1 模块划分（职责单一、可独立测试）

```
index.html            页面骨架：五个 Tab、弹层、toast 容器
css/style.css         全部样式（移动优先，375px 无横向滚动；桌面响应式 ≥768px）
js/storage.js         localStorage 读写：drugs / consumables / sales / ops / settings；导出/导入
js/parser.js          纯函数：OCR 文本行解析 → {条目候选, 数量}；匹配策略
js/ocr.js             Tesseract 懒加载（进度/错误回调）+ 图片预处理 + recognize
js/scanner.js         v4：条码扫码封装（BarcodeDetector → html5-qrcode 降级）
js/stats.js           纯函数：销售/成本/毛利/耗材使用统计聚合
js/app.js             状态管理、渲染、事件绑定、OCR 确认流程状态机、扫码流程
manifest.webmanifest  PWA 清单
sw.js                 Service Worker（precache + 缓存优先）
icons/                icon.svg + icon-192.png + icon-512.png + apple-touch-icon.png
docs/                 requirements.md / design.md / test.md
tests/                parser / storage / scanner / stats 单元测试
```

依赖方向：`app.js → ocr.js / scanner.js / parser.js / storage.js / stats.js`；`parser.js`、`storage.js`、`stats.js`、`scanner.js` 不依赖 DOM 与其他模块（可单测）。

### 3.2 数据结构（localStorage schema）

键名统一加前缀 `drugInventory.`：

```jsonc
// drugInventory.drugs
[
  {
    "id": "d_<ts>_<rand>",        // 唯一
    "name": "阿莫西林胶囊",         // 名称（必填）
    "spec": "0.25g*24粒",          // 规格（可选，可空 → null，US-14）
    "unit": "盒",                  // 单位（必填：输入框+常用建议，可自定义，US-13）
    "stock": 12,                   // 当前库存（整数，可为 0/负数）
    "threshold": 5,                // 预警阈值（默认 5，可改）
    "barcode": "6901234567890",    // 条码（可选，一药一码，唯一校验，US-15）
    "priceCost": 8.5,              // 进价（元，两位小数，可空 → null）
    "priceSell": 15.0,             // 卖出价（元，两位小数，可空 → null）
    "expiryDate": "2027-06-30",    // 有效期至（日期 YYYY-MM-DD，可空 → null，US-12）
    "createdAt": 1690000000000,
    "updatedAt": 1690000000000
  }
]

// drugInventory.consumables —— 耗材，独立于 drugs，但可售卖（US-9）
[
  {
    "id": "c_<ts>_<rand>",
    "name": "医用纱布",              // 名称（必填）
    "unit": "卷",                    // 单位（必填：输入框+常用建议：片/根/卷/瓶/袋/包/支/盒/个，可自定义，US-13；耗材无规格字段）
    "stock": 20,                     // 当前存量（整数，可为 0/负数）
    "threshold": 5,                  // 预警阈值（默认 5，可改）
    "initialStock": 20,              // 初始存量（创建时写入，编辑页只读展示，US-9）
    "priceCost": 3.0,                // 进价（元，可选 → null）
    "priceSell": 5.0,                // 卖出价（元，可选 → null）
    "createdAt": 1690000000000,
    "updatedAt": 1690000000000
  }
]

// drugInventory.ops —— 医疗操作（US-10），只增不改不删；items 为耗材使用明细快照
[
  {
    "id": "o_<ts>_<rand>",
    "type": "换药",                   // 操作类型（可自定义）
    "note": "",                       // 备注（可选）
    "items": [
      { "consumableId": "c_xxx", "name": "医用纱布", "unit": "卷", "qty": 2 }
    ],
    "createdAt": 1690000000000
  }
]

// drugInventory.sales —— 只增不改不删；保存名称/规格快照；类型 = 药品 | 耗材
[
  {
    "id": "s_<ts>_<rand>",
    "type": "drug" | "consumable",   // 记录类型（v3）：药品或耗材
    "drugId": "d_xxx",               // 药品 id；耗材记录为 null
    "consumableId": "c_xxx",         // 耗材 id；药品记录为 null（条目删除后字段仍保留）
    "name": "阿莫西林胶囊",           // 快照（药品名或耗材名）
    "spec": "0.25g*24粒",            // 快照（药品规格；耗材为 null）
    "unit": "盒",                    // 快照（药品单位或耗材单位）
    "qty": 2,                        // 销售数量（正整数）
    "priceSell": 15.0,               // 卖出价快照（元，可空 → null）；金额 = priceSell × qty（现场计算，不冗余存储）
    "source": "manual" | "ocr",
    "note": "",                      // 备注（可选）
    "createdAt": 1690000000000
  }
]

// drugInventory.settings
{ "formatVersion": 4, "lastImportAt": null }
```

- **唯一键**：药品 `name + spec`（US-1，**空规格视为一种取值**：同名且规格都空的药品仍判重，US-14；**规格空字符串 "" 归一化为 null**）；耗材建议名称唯一（重名提示）。**条码唯一**：非空条码全局唯一（一药一码，重复添加提示，US-15）。
- **扣减**：`stock = stock - qty`，**允许负数**（US-3 决策，负数表示已售未补，红色高亮 + 「欠 N」）；耗材**售卖与操作使用均扣减存量**（同规则，US-9）。
- **快照**：销售记录保存名称/规格/单位/卖出价快照；操作记录 items 保存耗材名称/单位快照——删除条目或改价后历史仍完整可读（US-5/US-8/US-10）。
- **价格**：`priceCost` / `priceSell` 均为可选（旧药品可为 null）；金额一律两位小数展示。
- **有效期**：`expiryDate` 为日期字符串（YYYY-MM-DD）或 null；临期定义 = 距到期 ≤ 90 天；已过期 = 到期日 < 今天。
- **条码**：`barcode` 为字符串或 null；扫码读出的码值（EAN-13 等条形码或二维码内容）统一存字符串。
- **导出/导入格式**：`formatVersion` 升为 **4**（v1=1、v2=2、v3=3）；导入**同时接受 v1/v2/v3/v4**（旧文件导入后新增字段补空：价格→null、expiryDate→null、barcode→null、consumables/ops→[]；未知/更高版本拒绝，D11 不变）。v1 基线说明：**v1 已上线运行，代码位于项目根目录，其导出格式即 formatVersion 1（drugs/sales 均无价格字段）**；v2 为价格/统计版；v3 为耗材/操作/有效期版。**加载时归一化**：首次以 v4 代码读取既有 localStorage 数据时同样补默认值（缺键→[]、缺字段→null），并将 settings.formatVersion 原地升级为 4。

### 3.3 界面结构与交互决策（与用户确认过的 UI 决策）

**全局**：全中文；底部固定 Tab 栏：**库存 / 登记销售 / 医疗 / 销售记录 / 统计**（5 个，v3）；页面内状态反馈用 toast；破坏性操作（删除、导入覆盖）一律二次确认弹层；**主要操作目标 ≥44×44px（N2）**。

| 页面 | 布局与行为 |
|---|---|
| **库存（药品）** | 药品列表卡片：名称、规格、单位、当前库存、预警阈值、卖出价、**有效期**。库存 ≤ 阈值 → 整卡**红色高亮**；库存 < 0 → 额外显示「欠 N」；**临期（≤90 天）→ 橙色标记「临期」；已过期 → 红色标记「已过期」**。右上角「＋」开添加弹层；右上角菜单（⋮）含：导出备份 / 导入备份 / 关于。列表为空显示引导文案。 |
| **添加药品弹层** | 表单：名称（必填）、**规格（可选，可留空）**、库存量（整数 ≥0，默认 0）、**单位（输入框+常用建议：盒/瓶/支，可输入任意单位，必填）**、预警阈值（整数，默认 5）、**条码（可选 +「📷 扫码」按钮自动填入）**、进价（可选，元）、卖出价（可选，元）、有效期至（可选，日期）。提交时校验必填与数字格式；名称+规格重复、条码重复 → 行内错误提示。成功 → toast + 关闭 + 列表刷新。 |
| **编辑/删除药品** | 库存卡片点击进编辑弹层（字段同上，含价格/有效期/条码，库存量可改）；卡片「删除」按钮 → 二次确认弹层 → 删除（销售记录保留）。 |

| **销售记录** | 倒序列表：时间、药品名、规格、单位、×数量、单价、金额小计、来源标签（手动/OCR）、备注；顶部筛选（药品名关键字 / 来源）。记录只读。 |

| **关于/备份提示** | 提示：localStorage 数据可能被浏览器清理，建议定期导出备份；微信内置浏览器 PWA 能力受限，建议用系统浏览器打开。 |

### 3.4 OCR 流程状态机（US-4 核心）

```
idle
 └─ 用户点「拍照识别」/「相册识别」
     ├─ (首次) loading：显示加载进度条（Tesseract 核心 + chi_sim 语言包）
     │     └─ 失败 → error：提示 + 重试/放弃按钮
     ├─ 图片 → canvas 预处理（缩放 ≤2000px、转灰度可选）→ recognize → 原始文本
     └─ confirming：解析后的【可编辑确认列表】
          每行 = [药品下拉（自动匹配建议，可改）| 数量输入（可改）| 删除行按钮]
          未匹配行 = 药品下拉为空 + 显示原始文本片段，供手动补选
          └─「确认扣减」→ 校验（数量>0、药品已选）→ 批量扣库存 + 写销售记录(source="ocr")
               → toast 成功 → 回到 idle
          └─「放弃」→ 丢弃识别结果，回 idle（不写任何数据）
```

**写入开关唯一**：确认列表的任何修改都发生在内存中，只有「确认扣减」才会调用 storage 写入（US-4 验收要点：扣减前不修改任何数据）。OCR 确认扣减时，卖出价取该条目**当前卖价快照**（确认列表不编辑价格，保持简洁）；**OCR 匹配候选同时包含药品与耗材**（匹配策略同 §3.5）；**过期药品在 OCR 确认列表中标记「已过期」并阻止该项扣减**（US-12）。

### 3.5 OCR 行解析规则（parser.js）

> 本节是解析规则的**唯一权威来源**；`docs/test.md` 的测试用例引用本节，不另行定义规则。

输入：Tesseract 输出的多行文本，逐行处理：

1. **匹配条目**：取该行文本在候选列表中的最佳匹配（策略 D7：精确 → 名称包含 → 无匹配返回 null）。候选列表由 app 层传入，**同时包含药品与耗材**（耗材售卖场景，US-9）；匹配规则不区分条目类型。
2. **提取数量**（仅从「药品名匹配位置之后」的文本提取，按优先级取第一个命中）：
   - 显式模式（不区分大小写）：
     - `x<正整数>` / `×<正整数>` / `*<正整数>`：如 `x2`、`×1`；
     - `<正整数><数量单位>`，单位 ∈ {盒, 瓶, 支, 袋, 片, 粒, 包, 根, 卷}：如 `2盒`、`2卷`；
     - `数量[:：]<正整数>`：如 `数量:2`；
   - 兜底模式：匹配位置之后第一个**独立整数**；
   - 全部失败 → 默认 **1**（确认列表中可改）。
3. **排除规则**：
   - 药品名**之前**的数字（如规格 `0.25g*24粒` 中的 `0.25`、`24`，或日期/编号）不参与数量判定；
   - 药品名之后有多个整数时，取**最靠近药品名**的一个；
   - 无药品名匹配的行不提取数量，整体作为未匹配行处理。
4. **数量合法性**：仅接受正整数；`0`、负数视为未命中，按第 2 条的兜底/默认规则处理。**小数（金额）**：显式数量标记（`x2`/`2盒`/`数量:2`）优先命中；仅当行内**无任何显式标记**时，才可能从金额小数取整数部分（如 `12.50 → 12`，v1 已固化行为）。对「药品名+单价」布局的小票，此类解析结果可在确认列表中修正（test.md 固定对应用例）。
5. **未匹配行**：进入确认列表，显示原始文本，由用户手动补选药品或删除该行。

### 3.6 PWA 与离线

- `manifest.webmanifest`：`name`、`short_name`、`theme_color`（医药绿）、`background_color`、`display: standalone`、`start_url: ./index.html`、`icons`（192/512 PNG + SVG）。
- `apple-touch-icon.png`（180×180）供 iOS 添加到主屏幕。
- `sw.js`：install 时 precache 静态资源清单（index.html/css/js/manifest/icons），activate 清理旧版本，fetch 缓存优先 + 网络回退。
- **托管约束（如实告知用户）**：Service Worker 仅在 HTTPS 或 localhost 可注册。因此：
  - 本地开发/临时使用：`python -m http.server` 或任意静态服务器；也可直接双击 `index.html`（`file://`）使用全部核心功能，但**无法安装到主屏幕、无法离线**；
  - 完整 PWA（安装+离线）：需托管到任意 HTTPS 静态站（GitHub Pages / Netlify / 云厂商对象存储等），`docs/` 中提供部署说明。
- 微信内置浏览器：不支持 PWA 安装，页面内提示引导用系统浏览器。

### 3.7 条码扫码（US-15，纯本地免费方案）

```
idle
 └─ 用户点「扫码」（添加药品表单 / 登记销售页）
     ├─ (首次) loading：原生 BarcodeDetector 不可用 → CDN 懒加载 html5-qrcode
     ├─ scanning：打开扫码弹层，调起摄像头取景（需 HTTPS + 摄像头权限）
     │     └─ 权限拒绝/无摄像头 → error：提示改用「手动输入条码」
     ├─ 读到码值（EAN-13 等条形码或二维码内容，统一存字符串）
     ├─ 添加药品表单：自动填入条码字段
     │     └─ 码已存在 → 提示「该条码已收录：<药品名>」（名称/规格仍需手动输入）
     └─ 登记销售：匹配库存中该条码药品
           ├─ 命中 → 自动选中该药品（填数量 → 确认扣减）
           │     └─ 命中药品已过期 → **阻止选中并提示「已过期」（同手动下拉逻辑，US-12）**
           └─ 未命中 → 提示「未收录，请先添加该药品并录入条码」
```

- **纯本地**：只匹配自己库存中的条码字段，不联网、不查外部药品库（用户确认：先不做联网识别）；
- **依赖**：`BarcodeDetector`（Android Chrome 支持）优先；不可用时懒加载 `html5-qrcode`（CDN，类似 OCR 模式，失败可重试/放弃）；**APK/Capacitor 环境**（WebView 无 BarcodeDetector、getUserMedia 实测不可用）→ 走原生扫码插件 `@capacitor/barcode-scanner`（scanner.js 通过 Capacitor 桥接调用系统摄像头，D26）；
- **隐私**：扫码画面仅本地处理，不上传（符合 N6）。

### 3.8 桌面端适配（US-16，纯样式/文案，不改 schema）

- PWA 安装能力已具备（§3.6：HTTPS + manifest + 图标 + SW），Chrome/Edge 桌面可直接安装；
- **桌面响应式**（`@media (min-width: 768px)`）：`.app` 内容区加宽至 960px；药品/耗材列表改为自适应多列网格；表单、弹层（modal-card）居中加宽（≤640px）；字体与间距按桌面优化；
- **桌面交互细节**：表单 Enter 提交；按钮 `:hover` 悬停效果（手机端保持 `:active` 不变）；
- **安装引导**：关于页 + README 写明 Windows 安装步骤（Chrome/Edge 打开线上网址 → 地址栏右侧安装图标 → 安装）；
- 空间：保持现有极小体积（约 165KB），不引入构建/压缩步骤（D23）。

### 3.9 APK 打包（US-17，GitHub Actions 云端构建）

- **原理**：GitHub Actions（ubuntu runner 自带 Android SDK/JDK/Java）用 **Capacitor** 把网页版（webDir = `deploy-dist`）包装成 Android WebView 应用，`gradlew assembleDebug` 产出**调试签名 APK**（约 15~20MB，个人使用足够）；
- **仓库结构**（**定案：与主仓库同仓库** `.github/workflows/build-apk.yml`；独立仓库 `drug-inventory-apk` 为备选）：
  - `capacitor.config.json`：`webDir: "deploy-dist"`、`appId: com.xiaodian.druginventory`、`appName: 药品库存管理`；
  - `package.json`：`@capacitor/core`、`@capacitor/cli`、`@capacitor/android`、`@capacitor/barcode-scanner`（仅构建依赖；后者供 APK 原生扫码，D26——**官方插件**，替代已归档且无 Capacitor 6 版本的社区插件 `@capacitor-community/barcode-scanner`，`native.android.scanningLibrary='zxing'` 免 Google Play 服务）；
  - `.github/workflows/build-apk.yml`：push 触发 → checkout → setup-node → `npm ci` → `npx cap add android` → `npx cap sync` → `cd android && ./gradlew assembleDebug` → `actions/upload-artifact` 产出 APK（+ `workflow_dispatch` 手动触发）。**幂等与同步**：android/ 不提交、每次全新生成（`cap add` 前检查目录不存在）；**deploy-dist 随仓库提交**并与网页源码保持同步（或 workflow 在 `cap sync` 前先复制网页文件到 deploy-dist）；`cap add` 后注入 CAMERA 权限（见下）；
- **权限与扫码**：Capacitor 默认 manifest **仅含 INTERNET**——workflow 在 `cap add` 后向 `AndroidManifest.xml` 注入 `<uses-permission android:name="android.permission.CAMERA"/>`（原生扫码插件 `@capacitor/barcode-scanner` 亦自带 CAMERA 声明），并同步将 `android/variables.gradle` 的 `minSdkVersion` 提升到 **26**（官方插件要求）；**APK 内扫码不走网页摄像头**（WebView 不支持 getUserMedia，实测确认），scanner.js 检测到 Capacitor 环境时调用原生插件（D26）；数据存 APK 内 WebView 的 localStorage，**与网页版互相独立**（导出/导入迁移）；
- **说明**：本机无 Android SDK，**APK 构建无法本地验证**——由 Actions 云端构建结果验证（构建失败时迭代修复 workflow）；APK 为补充交付，网页版 PWA 仍是体积最小、自动更新的首选。

| 风险 | 影响 | 缓解 |
|---|---|---|
| Tesseract CDN（jsdelivr）在弱网/网络环境受限 | OCR 加载失败 | 进度+失败提示、重试按钮；预留备用 CDN（unpkg）常量可切换 |
| 机打小票排版多样，解析不 100% 准确 | 数量/药品误判 | 确认列表可编辑 + 未匹配行手动补选（D5）；默认数量 1 兜底 |
| 手写单据识别率低 | 识别结果不可用 | 需求明示不承诺手写准确率，手动登记（US-3）兜底 |
| localStorage 被清理 / 容量超限 | 数据丢失 | 导出/导入备份（US-6）+ 关于页提醒 |
| 微信内置浏览器不支持 PWA 安装 | 无法加主屏/离线 | 页面提示改用系统浏览器；file:// 与 HTTPS 两种用法都写明 |
| SW 缓存更新不及时 | 用户看到旧版本 | sw.js 版本号 + activate 清旧缓存 |
| 价格漏录/录错导致统计失真 | 毛利不准 | 统计页注明口径：售价用快照（改售价不影响已记录销售额），成本按统计时当前进价计算（改进价会影响历史毛利，属已知口径）；价格可随时编辑修正 |
| 金额精度（浮点误差） | 统计分位误差 | 金额计算以「分」为单位取整（×100 后计算，展示时还原为元） |
| 过期药品被售出 | 健康风险 | 临期/过期高亮标记（AC40）；过期药品销售阻止（AC41）；有效期漏录则无提醒（如实说明） |
| 操作关联耗材误选/漏选 | 耗材存量与统计失真 | 操作确认后才写入（复用 D5 精神）；明细可编辑、行可删 |
| 日期跨时区/格式错误 | 临期/过期判断错误 | 有效期以本地日期字符串 YYYY-MM-DD 存储，判断用本地时区当日 0 点 |
| 摄像头兼容性差异 | 扫码不可用 | 浏览器：BarcodeDetector 优先 + html5-qrcode 降级；**APK：原生插件（D26）**；扫码失败/无权限 → 手动输入条码兜底 |
| 条码误绑/扫错码 | 销售选错药品 | 扫码命中后仍在确认列表可见可改（与 OCR 一致的人工确认精神） |
| APK 云端构建失败（版本/依赖变动） | 无法产出 APK | workflow 含 workflow_dispatch 手动触发 + Actions 日志可查，迭代修复；网页版不受影响 |
| APK 数据与网页版割裂 | 用户困惑 | README 明确「导出/导入迁移」说明；APK 为补充，PWA 为主 |
