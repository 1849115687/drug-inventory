# 需求文档 — 药品销售库存管理小程序（PWA）

> 项目目录：`drug-inventory-app/`
> 文档状态：**已确认**（2026-08-29，用户逐项确认）
> 配套文档：`docs/design.md`（设计）、`docs/test.md`（测试，实现阶段产出）

## 1. 总体目标

为药店/零售店提供一个**在手机上运行的药品销售与库存管理小程序**：无后端、纯前端、数据存于浏览器 localStorage，支持拍照/相册识别销售单自动扣减库存，可添加到手机主屏幕离线使用。

## 2. 功能用户故事

### US-1 添加药品
**作为**店员，**我想要**添加药品（名称、当前库存量、单位、预警阈值【默认 5，可单独设置】，规格可选填），**以便**建立库存台账。

验收要点：
- 表单必填：名称、库存量、单位、预警阈值（数字，默认 5）；**规格可选填**（可留空，US-14）
- **单位 = 输入框 + 常用建议**（盒/瓶/支…可点击快速选，也可手动输入任意单位，US-13）
- 库存量可为 0 或正整数
- 药品以「名称 + 规格」唯一标识（**空规格视为一种取值**：同名且规格都空仍判重）：重复添加时提示已存在，不创建重复条目
- 添加成功后库存列表立即更新

### US-2 查看库存列表与低库存提醒
**作为**店员，**我想要**查看所有药品列表并看到实时库存，**以便**掌握库存情况、及时补货。

验收要点：
- 列表项展示：名称、规格、单位、当前库存、预警阈值
- 库存 ≤ 预警阈值（含负数）时，条目红色高亮提醒
- 负数库存额外明确标记（如「欠 N」），代表已售未补

### US-3 手动登记销售
**作为**店员，**我想要**在没有单据时手动登记销售（选择药品或耗材 + 数量 → 自动扣减库存 → 记入销售记录），**以便**快速入账。

验收要点：
- 从已有药品或耗材中选择（支持搜索，下拉标注「药品/耗材」类型），输入销售数量（正整数）
- 扣减后库存/存量立即更新；数量超过库存时**不阻止**，允许扣成负数并按 US-2 高亮
- 每次登记自动生成一条销售记录（来源 = 手动，记录类型 = 药品/耗材）

### US-4 拍照/相册识别销售单（OCR）
**作为**店员，**我想要**拍照或从相册选择销售单图片，由程序识别出药品名称与销售数量，经我**确认/修正后**批量扣减库存，**以便**省去逐条手工录入。

验收要点：
- 拍照（相机）与相册选择两个入口（HTML input capture）
- Tesseract.js **懒加载**：首次点击识别入口时才加载（含中文语言包），显示加载进度，失败有明确提示
- 识别结果以**可编辑确认列表**呈现：每行 = 药品名（自动匹配库存建议）+ 数量；未匹配的行可手动补选药品、修正数量
- 用户点击「确认扣减」后才批量写入：扣库存 + 生成销售记录（来源 = OCR）
- 扣减前不修改任何数据（确认是唯一写入开关）
- 手写单据识别率低：不承诺手写准确率，用户可随时放弃 OCR 改走手动登记（US-3）

### US-5 销售记录追溯
**作为**店主，**我想要**查看每一次销售记录（时间、药品、规格、单位、数量、来源【手动/OCR】、备注），**以便**追溯销售情况。

验收要点：
- 记录按时间倒序展示，可按药品名/来源筛选
- 记录只增不改不删（v1 不做删除）
- 药品被删除后，其历史销售记录仍保留（记录中保存名称/规格快照）；药品的**编辑/删除**为隐含生命周期功能（删除需二次确认，历史记录保留）

### US-6 数据导出/导入备份
**作为**店主，**我想要**把库存与销售数据导出为 JSON 文件，并可从文件导入恢复，**以便**在浏览器清理数据或更换手机时防止丢失。

验收要点：
- 导出：下载包含全部数据（药品、销售记录、设置）的 JSON 文件
- 导入：选择 JSON 文件 → 格式校验 → 二次确认后写入
- 界面提供备份提示（告知 localStorage 数据可能被浏览器清理）

### US-7 药品价格管理
**作为**店主，**我想要**为药品设置进价和卖出价，**以便**掌握成本与售价、为利润统计提供基础。

验收要点：
- 添加/编辑药品表单增加「进价」「卖出价」字段（单位：元，两位小数，均可留空）
- 库存列表显示卖出价；进价在编辑页可见（不区分角色，用户已确认全部可见）
- 旧药品（无价格）正常显示与编辑，不报错

### US-8 利润统计
**作为**店主，**我想要**按日期区间和按药品查看销售额、成本、毛利，**以便**掌握经营利润。

验收要点：
- 底部新增「统计」Tab（库存 / 登记销售 / 医疗 / 销售记录 / 统计）
- 汇总卡片：总销售额、总成本、总毛利、毛利率（**包含药品与耗材售卖**）
- 按日期查看：日 / 月 / 自定义区间筛选
- 按药品查看：每个条目的销量、销售额、成本、毛利，可排序（**含耗材，标注类型**）
- 销售记录保存**卖出价快照**（售价变更不影响历史记录）
- 无价格的历史记录不计入成本/毛利统计（界面注明统计口径）

### US-9 医疗耗材独立管理
**作为**医护人员，**我想要**独立管理医疗耗材（创可贴/棉签/纱布等）的存量，**以便**掌握耗材库存、及时补货；耗材既可被医疗操作使用，也可直接售卖。

验收要点：
- 耗材条目：名称、**单位（输入框+常用建议：片/根/卷/瓶/袋/包/支/盒/个，可手动输入任意单位，US-13）**、当前存量、预警阈值（默认 5，可设置）、初始存量、**进价/卖出价（可选，同药品）**
- 耗材与药品**分开管理**（各自列表、各自记录），但**售卖混选**（登记销售时药品+耗材可同时选）
- 「进货/调整存量」功能；存量 ≤ 阈值红色高亮；负数显示「欠 N」
- **耗材售卖**：在登记销售中选择耗材售卖 → 扣减耗材存量，生成销售记录（类型=耗材）
- **耗材使用**：医疗操作关联耗材 → 同样扣减耗材存量并记入使用量
- 删除耗材需二次确认（历史销售/操作记录保留）

### US-10 医疗操作记录
**作为**医护人员，**我想要**记录每次医疗操作（如换药）及其耗材使用，**以便**操作可追溯、耗材使用自动入账。

验收要点：
- 记录：时间 + 操作类型（可自定义，如换药/清创/消毒…）+ 备注
- **关联耗材**：勾选本次使用的耗材与数量 → **自动扣减耗材存量**并记入使用量
- 操作历史列表（倒序，可按类型筛选）
- 耗材扣减允许负数（与药品一致），操作确认后才写入

### US-11 耗材使用统计
**作为**医护人员，**我想要**按时间区间和按耗材查看使用量，**以便**掌握耗材消耗情况。

验收要点：
- 统计 Tab 增加「耗材使用」视图（与销售统计切换）
- 按日期区间（日/月/自定义）与按耗材两种查看方式
- 使用量 = Σ(操作明细中该耗材的数量)

### US-12 药品有效期管理
**作为**店员，**我想要**记录药品有效期并得到临期/过期提醒，**以便**避免售出过期药品。

验收要点：
- 药品加「有效期至」字段（日期，可空）；添加/编辑可设置
- 列表显示有效期；**临期（≤90 天）高亮**；**已过期红色标记**
- **过期药品在销售（手动/OCR 确认）时提示并阻止**，先处理库存
- 每药一个有效期（简化方案，以最近批次为准，不做批次管理）

### US-13 单位可手动输入
**作为**店员，**我想要**药品和耗材的单位可以输入任意值，**以便**适应各种包装规格（贴/套/支装等）。

验收要点：
- 药品单位、耗材单位均为**输入框 + 常用建议列表**（可点击快速选择，也可自行输入任意单位）
- 单位必填；任意文本可保存

### US-14 规格可选填
**作为**店员，**我想要**添加药品时规格可以留空，**以便**简化录入。

验收要点：
- 药品表单「规格」改为**可选填**（可留空）
- 唯一键 = 名称 + 规格（**空规格视为一种取值**：同名且规格都空的药品仍判重）
- 列表/销售记录/统计中规格为空显示「—」；OCR 匹配、销售、统计逻辑兼容空规格

### US-15 条码扫码匹配
**作为**店员，**我想要**用手机摄像头扫描药品条码/二维码，**以便**快速找到或录入药品（纯本地免费方案）。

验收要点：
- 药品加「**条码**」字段（可选；一药一码，重复提示）
- **添加药品表单**：扫码按钮 → 摄像头读码 → 自动填入条码字段；该码已收录 → 提示已存在该药品（名称/规格仍需手动输入）
- **登记销售**：扫码按钮 → 读码 → 匹配并选中库存中该条码药品；未收录 → 提示先添加
- 实现：原生 `BarcodeDetector` 优先，降级 `html5-qrcode`（CDN 懒加载）；需摄像头权限与 HTTPS

### US-16 桌面 App 适配与安装
**作为**店主，**我想要**在 Windows 电脑上把应用安装为桌面 App 并使用，**以便**电脑上也能快速操作。

验收要点：
- 应用满足 PWA 安装条件（HTTPS/manifest/图标/SW），Chrome/Edge 可直接安装为桌面应用
- 窗口 ≥768px 时内容区加宽（960px）、药品/耗材列表自适应多列网格、表单与弹层居中加宽
- 表单支持回车提交；按钮有鼠标悬停效果
- 关于页与 README 提供桌面安装引导文案
- **安装占用空间极小（约 165KB）**；OCR/扫码库按需 CDN 加载，不占安装空间

### US-17 APK 安装包（Android）
**作为**店主，**我想要**一个可直接安装的 Android APK 包，**以便**手机上以原生应用的方式使用（接受体积 15~20MB）。

验收要点：
- 用 Capacitor 将网页版打包为 Android WebView 应用，产出可安装 APK（调试签名，个人使用足够）
- **云端构建**（GitHub Actions，无需本机装 Android SDK）：推送到仓库自动构建，产出 APK 供下载
- APK 内核心功能可用（扫码/OCR 自动申请相机权限）；数据与网页版互相独立（导出/导入迁移）
- 后续改功能可重新触发构建更新 APK

## 3. 非功能标准

| 编号 | 类别 | 标准 | 衡量方式 |
|---|---|---|---|
| N1 | 移动端适配 | 手机浏览器为主要目标；375px 宽度下无横向滚动 | 移动视口逐页检查 |
| N2 | 触控体验 | 主要操作目标 ≥ 44×44px | 检查关键按钮/条目尺寸 |
| N3 | 离线能力 | 添加到主屏幕后，断网可打开并使用核心功能 | 断网后打开应用验证 |
| N4 | 数据持久化 | 刷新/关闭后重开，数据不丢失 | 操作后刷新验证 |
| N5 | OCR 可用性 | 语言包懒加载、有进度提示；加载失败有明确反馈 | 弱网/断网首次使用验证 |
| N6 | 安全性 | 除 CDN 加载 OCR 库/语言包与扫码库外，无任何业务数据外发 | 代码审查确认无网络请求 |
| N7 | 兼容性 | 现代移动浏览器（Chrome / Safari）；微信内置浏览器尽力兼容（PWA 能力受限，需提示） | 目标浏览器手测 |
| N8 | 界面语言 | 全中文界面，简洁清晰 | 走查 |

## 4. 范围界定（v1 不做）

- ❌ 后端服务器、账号登录、多设备同步
- ❌ 药品批号 / 供应商管理、批次管理（有效期已支持，见 US-12）
- ❌ 手写单据的高精度识别（不承诺，手动录入兜底）
- ❌ 保存销售单原图（仅保存 OCR 识别文本）
- ❌ 销售记录的修改与删除（只增不改）
