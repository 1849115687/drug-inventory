# 测试文档 — 药品销售库存管理小程序（PWA）

> 配套文档：`docs/requirements.md`（需求，已确认）、`docs/design.md`（设计）
> 解析规则**唯一权威**：design.md §3.5（本测试不另立规则，仅引用并细化可测用例）
> 自动化测试：`tests/parser.test.js`、`tests/storage.test.js`、`tests/scanner.test.js`、`tests/stats.test.js`，运行 `node --test "tests/*.test.js"`（131 用例：parser 23 + storage 56 + scanner 31 + stats 21）

## 1. 测试用例（按用户故事映射）

### US-1 添加药品

| 编号 | 关联 | 输入 | 预期输出/行为 |

| T1-1 | US-1/AC1 | 表单：名称「阿莫西林胶囊」、规格「0.25g*24粒」、库存 10、单位 盒、阈值 5，提交 | 添加成功；toast「已添加」；库存列表即时出现该药品（含库存 10 与阈值 5）；`drugInventory.drugs` 写入 1 条 |

| P16 | 第4条 金额例外 | 「阿莫西林胶囊 12.50」 | 金额小数取整数部分 → 12（§3.5「金额整数部分除外」） |
| P17 | 第3/5条 未匹配行 | 「未知药品 5盒」 | 未匹配行 qty 占位 1，不按 5 处理 |
| P18 | 输入清理 | 多行文本含空行/全角空格 | 空行忽略；全角空格不影响匹配与数量提取 |

> 测试意图说明（§3.5 解释口径，供评审确认）：数量提取在保留空白的前提下进行（避免 "2 12.50" 合并为 "212.50" 误判）；规格文本若出现在药品名之后则整体跳过；金额小数（如 12.50）按 §3.5 例外条款取其正整数部分；小数数量（如 1.5盒）中「5盒」因前置小数点不成立，兜底取整数部分 1。所有结果均在确认列表中可人工修正（D5），不影响数据准确性。
